# Frontend and UI

- Follow existing component, routing, state, styling, accessibility, and localization patterns.
- Define loading, empty, success, validation, unauthorized, retry, and error states.
- Preserve direct navigation, refresh, keyboard access, responsive behavior, and focus management where relevant.
- Avoid introducing a new state or design abstraction for a local change without clear benefit.
- Verify behavior in the running application when practical; a successful build is not a UI check.
- Keep user-visible copy and API error mappings consistent with the approved contract.
